> **P2-05 — Diff-only scan mode** — ✅ done, merged as [argus-oss#50](https://github.com/WeaversMask/argus-oss/pull/50). `argus check --diff <ref>` narrows a scan to a branch's own work, in two independent steps: discovery drops files the diff never touched, and `filterToChangedLines` drops violations that miss a changed line — **the second is not optional**, because a file with a one-line edit is still parsed whole and would otherwise report every pre-existing finding in it. **The interesting decisions were all about what "changed since main" means, and each has a silent failure mode:** the comparison runs from the **merge base** (a two-dot `git diff main` reports post-branch-point work on `main` as reversals, attributing a colleague's changes to you) against the **working tree** (`HEAD` would put line numbers out of step with the bytes the scanner reads), with **untracked files included whole** (git diffs only what it tracks, so the newest code in a change would otherwise report nothing) and **rename detection off** (a pure rename yields no hunks, i.e. total suppression). Every git failure exits `2`; a fall back to scanning everything reads as a regression and one to scanning nothing reads as a pass. **`packages/orchestrator/` exists as of this task**, with the boundary recorded in [ADR-0008](./adr/0008-scan-scope-orchestration.md): git is an injected `GitRunner`, **not** a core port — the domain has no VCS concept, and a port invented so an adapter has something to implement is fiction. That injection is what let 48 orchestrator tests cover the diff grammar (omitted hunk counts, `/dev/null` targets, binary files, C-quoted paths, `\ No newline`) with no repository on disk, while `apps/cli/tests/git.test.ts` exercises the real subprocess once. **Two traps worth carrying forward:** hunk bodies are stepped over by _counting_ the lines the header promises, because an added line reading `+++ b/other.ts` is indistinguishable from a header — mis-parsing it attributes a file's changes to the wrong path, which no output reveals; and the path vocabulary is string arithmetic on `git rev-parse --show-prefix`, deliberately not `realpath`, because on macOS the same directory is `/var/folders/…` to Node and `/private/var/folders/…` to git and any absolute-path comparison matches nothing. The dogfood scan caught this task making `planScan` complexity-12/69-lines and `diff-extractor.ts` 356 lines; both were split rather than the thresholds widened. **The cross-family full-packet review (REQUEST CHANGES, then all findings fixed) is the row's real lesson:** all three of its findings landed inside the defence `DIFF_FLAGS` already claimed to provide — `diff.interHunkContext` reintroduces context despite `--unified=0`, `diff.relative` empties the change set whenever the project root sits below the repo root, and plain git appends a **trailing tab** to any path containing a space, which made a change-set key no discovered file could match. That last one needs no unusual config at all. Every one is invisible from this repo's own layout (no spaces in paths, project root == repo root, default git config), so no amount of dogfooding here would have found them — **a parser fed by a tool you do not control has to be probed against that tool, not against your repo.** `skipHunkBody` now also stops at any line that cannot be a hunk body, so a header disagreeing with its body re-synchronises instead of swallowing the next file. **A second review pass then found that fix incomplete:** the `---`/`+++` pairing it added is necessary but not sufficient, because content forges the pair (`-- x` renders as `--- x`, `++ b/evil.ts` as `+++ b/evil.ts`) — and `diff.submodule=diff` reaches the same desynced walk through **plain config, no environment variable**. The structural fix is that `parseDiff` refuses to re-target for anything but a `diff --git ` line while desynced, a marker content cannot impersonate; `--submodule=short` pins the config half. **The transferable lesson is about the tests, not the parser:** the first fix's own regression test used a shape that could not fire, and two successive end-to-end attempts passed while exercising nothing (an env var injected through `CliIO` never reaches a subprocess that inherits `process.env`; a forged line written as a comment renders `-// …` and forges nothing). Disabling the fix and requiring the test to fail is what caught all three.
