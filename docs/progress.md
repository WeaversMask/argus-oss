What Argus has actually shipped, in order, in plain language. One entry per merged task: what a reader can **do** now that they could not before.

**A note on the links.** Argus's history spans two repositories. Everything up to 2026-07-04 was built in a private repo that was later scrubbed of the maintainer's personal email and retired; that repo is frozen and will never be public, so its pull-request links would be dead. Entries from that period link the **merge commit** in this repository instead — the commits themselves carried over. From SEC-02 (2026-07-05) onward, entries link the pull request.

Routine dependency bumps and generated-file regenerations are not listed; they are in the git history. Security-advisory fixes are, because they changed what the tree was exposed to.

---

## Where things stand today

**Argus runs.** `argus check .` scans a TypeScript/JavaScript project against ten built-in rules and reports findings to a terminal or as JSON; `argus fix` repairs some of what it finds; `argus explain` describes a rule. It scans its own repository on every pull request and fails the build on any finding. Phases 0 and 1 are complete; Phase 2 (the MVP) is nearly so.

**It is not released.** Nothing is published to npm, every package is still private at version `0.0.0`, and the packaging decision is deliberately deferred. Argus is a working tool you would have to clone to use, not a dependency you can install.

- **2026-08-02 — P2-05 Scan only what you changed** ([#50](https://github.com/WeaversMask/argus-oss/pull/50))
  `argus check . --diff main` reports the violations your branch introduced and nothing else — the difference between a CI comment a reviewer reads and one they learn to scroll past. A file you touched on one line is still analysed in full, but a finding forty lines above your edit is not yours to answer for. It compares against the commit you branched from, so work landed on `main` since is never attributed to you, and against your working tree, so uncommitted edits count. New files are covered even before they are added to git — the newest code being the likeliest place for a fresh problem. A ref git cannot resolve is an error rather than a quiet fall back to scanning everything or nothing.

- **2026-08-04 — OPS-07 A quality gate that never checked anything** ([#52](https://github.com/WeaversMask/argus-oss/pull/52))
  One of this project's four mandatory pre-push checks turned out to be doing nothing at all, and had been since the checks were written. `pnpm build` was listed as required in the contributor instructions, run as its own job on every pull request, and reported as green in almost every handover — but none of the ten packages in this repository is built, so the command exited successfully having executed zero tasks. A build step was not the fix: the packages are deliberately unbuilt, and the type checker was already proving they compile. So the requirement was withdrawn and replaced with one that verifies the remaining checks actually reach every package — because the same silent-success problem was one careless change away in two other places. The command itself was left alone: it becomes real once the tool is bundled, and deleting it would have meant undoing that shortly afterwards. The lesson is the reason it survived so long: a check that passes while doing nothing is worse than no check at all, because everyone cites it as evidence.

- **2026-08-09 — SEC-03 A security pin that three advisories walked straight past** ([#54](https://github.com/WeaversMask/argus-oss/pull/54))
  A dependency this project has never chosen, and does not import, stopped every pull request in the repository from merging. `js-yaml` arrives underneath the configuration loader, four levels down; a new advisory said the version in use burns unbounded CPU on a crafted YAML document, and the audit gate — correctly — refused to let anything through until it was dealt with. The fix is one character wide. What made it worth writing down is that a pin against exactly this package already existed, and had already been stepped over twice before: each new advisory declared a wider range of bad versions than the last, sailing past a pin written to stop the previous one. A pin is a snapshot of what was known on the day it was written, not a wall. The second finding was in the note beside it. That note described this package as reaching only the development tooling, which would have made it a tidiness concern rather than an urgent one — but it also travels into the code this project would actually ship, and nobody had re-checked since the configuration loader was built. Both are now recorded, along with the one version that cannot be fixed at all: an older copy, used only by a release tool, for which no corrected release exists and which cannot be forced forward without breaking the tool that needs it. It is confined to development and sits below the threshold the full-tree check enforces, so it is written down as accepted rather than left to be rediscovered.
